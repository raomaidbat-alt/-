# Промт: редизайн отчёта «Оперативная сводка»

Скопируй всё ниже в чат с ИИ-разработчиком (Claude Code, Cursor и т.п.) или отдай разработчику как ТЗ.

---

## Роль и задача

Ты senior frontend-разработчик и дизайнер аналитических интерфейсов. Нужно переделать внутренний отчёт «Оперативная сводка» по сделкам Bitrix24. Сейчас это набор белых вкладок со списками. Отчёт должен стать дашбордом, по которому руководитель за 30 секунд понимает: где горит, у кого из менеджеров, сколько денег под риском и что стало лучше или хуже со вчера.

Визуальный язык и технические решения бери из нашего маркетингового дашборда «Воронка продаж и каналы» (ФОРАЙТИ). Оба отчёта должны выглядеть как части одного продукта.

## Что есть сейчас

Шапка: заголовок «Оперативная сводка», время снимка («Снимок сформирован: 2026-09-29 18:00»), выбор даты снимка.

Вкладки-пилюли:
1. Обзор: 7 плиток с числами (Просроченные дела 5, Сделки без дел 34, Зависшие сделки 38, Просроченные задачи 2, Звонки 0, Выигранные 2, Проигранные 1). Ниже списки «менеджер: количество» по трём проблемам.
2. Просроченные дела: таблица Сделка, Менеджер, Воронка, Стадия, Тип дела, Название дела, Дедлайн, Дней просрочки.
3. Без дел: Сделка, Менеджер, Воронка, Стадия, Создана.
4. Зависшие: Сделка, Менеджер, Воронка, Стадия, На стадии с, Рабочих дней.
5. Просроченные задачи: Задача, Менеджер, Дедлайн, Дней просрочки, Сделка.
6. Звонки, 7. Выигранные, 8. Проигранные, 9. Счета.

Фильтры на вкладках: воронка, менеджер, сортировка (выпадающие списки).

Проблемы текущего вида:
- Плитки все одинаковые. Не видно, какая цифра плохая, какая нормальная, выросла она или упала.
- Нет денег. Не видно, на какую сумму зависли сделки.
- Одна и та же сделка лежит в трёх вкладках (без дел, зависла, просрочено дело), и картину по ней приходится собирать вручную.
- Красный бейдж «0» в колонке «Дней просрочки» выглядит как ошибка. На самом деле это просрочка сегодня.
- Нет динамики: непонятно, разгребают завал или он копится.
- Звонки 0: непонятно, это правда ноль или данные не подтянулись.
- Сортировка отдельным селектом вместо клика по заголовку колонки.
- Длинные таблицы без группировки, итогов и поиска.

## Стек (как в маркетинговом дашборде)

- React 19 + TypeScript, сборка Vite. Основной экран в одном файле-компоненте (`OpsSummaryDashboard.tsx`), без внешнего стейт-менеджера: `useState`, `useMemo`, `useCallback`.
- Tailwind CSS v4 (цвета через CSS-переменные, см. раздел «Тема»).
- Recharts для графиков: `AreaChart`, `BarChart`, `ResponsiveContainer`, `Tooltip`.
- lucide-react для иконок.
- Форматирование через `Intl.NumberFormat('ru-RU')` и `Intl.DateTimeFormat('ru-RU')`: `fmtInt`, `fmtMoney` (₽, без копеек, компактный режим «1,2 млн ₽» для плиток), `fmtPct`, функция `plural(n, 'сделка', 'сделки', 'сделок')`.
- Все числа с `tabular-nums`, числовые колонки выровнены вправо.
- Данные приходят одним JSON с бэкенда (контракт ниже). Вся агрегация, фильтрация и сортировка на клиенте через `useMemo`.
- Демо-режим: `VITE_DEMO=1` включает генератор тестовых данных с фиксированным сидом (`mulberry32(seed)`), чтобы дизайн можно было показать без доступа к CRM.
- Доступ по токену (как в маркетинговом дашборде): отчёт содержит имена сотрудников и названия сделок, открытым он быть не должен.

## Тема и стиль

Тёмная тема по умолчанию, светлая переключается кнопкой (Sun/Moon) и запоминается в `localStorage`. Тема ставится скриптом в `<head>` до первого рендера, чтобы не мигал белый фон.

Фирменная палитра ФОРАЙТИ:
- фон `#07142f`, в шапке мягкое свечение: `radial-gradient(900px 520px at 88% -8%, rgba(37,99,235,.45), transparent 60%)` и `radial-gradient(700px 420px at -10% 110%, rgba(255,122,26,.10), transparent 60%)`;
- в тёмной теме нейтральные `zinc` подменяются на тёмно-синие через переменные на корневом элементе: 50 `#f5f7fd`, 100 `#e8edf8`, 200 `#cfd8ee`, 300 `#a9b7dc`, 400 `#8595c2`, 500 `#6474a3`, 600 `#46568a`, 700 `#2a3d73`, 800 `#1a2c5e`, 900 `#0f1f4a`, 950 `#07142f`;
- акцент оранжевый `#ff7a1a`, основная кнопка с градиентом `#ff8a2e → #f06400` и тенью `0 4px 14px rgba(255,122,26,.3)`;
- смысловые цвета: синий `#3b82f6` (в работе, нейтральная метрика), зелёный `#10b981` (хорошо, выиграно), жёлтый `#f59e0b` (внимание), красный `#ef4444` (плохо, просрочено).

Шрифты: заголовки Montserrat 700/800, текст Inter 400-700 (Google Fonts). Над заголовком маленькая надпись капсом оранжевым: «ФОРАЙТИ · ОПЕРАТИВНАЯ СВОДКА».

Базовые компоненты (скопировать из маркетингового дашборда и переиспользовать):
- `Card`: `rounded-xl border border-zinc-200 bg-white shadow-sm dark:border-zinc-800 dark:bg-zinc-900/60`.
- `CardHeader`: иконка lucide серым, заголовок `text-sm font-semibold`, под ним описание `text-xs text-zinc-500`, справа слот для действия.
- `KpiCard`: иконка в квадрате, цветная полоска-акцент сверху, крупное число, бейдж дельты, строка-подсказка.
- `Badge` с тонами `positive / negative / warning / info / neutral` (фон 10%, текст, `ring-1 ring-inset`).
- `DeltaBadge`: стрелка и процент к прошлому периоду. Для метрик «чем меньше, тем лучше» (просрочки, зависшие) цвет инвертирован: рост красный, падение зелёное.
- Цветной чип сущности: квадрат 24px с иконкой, фон цвета с прозрачностью `${color}1a`, иконка цветом. Использовать для воронок и менеджеров (у менеджера вместо иконки инициалы).

Адаптив: сетка плиток `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`, отступы по краям 16px на телефоне, таблицы в `overflow-x-auto` с `min-width`. На ширине меньше 640px строки таблиц превращаются в карточки. Горизонтальной прокрутки страницы быть не должно.

## Структура нового отчёта

### 1. Шапка

- Слева: надпись бренда, заголовок «Оперативная сводка» (Montserrat), под ним «Снимок от 29 сентября, 18:00» и бейдж свежести: зелёный «Актуально», если снимок сегодняшний; жёлтый «Устарел», если старше суток.
- Справа: выбор даты снимка со стрелками «предыдущий / следующий день», фильтры «Воронка» и «Менеджер» (мультиселект, выбранные значения видны чипами с крестиком), переключатель темы.
- Фильтры глобальные: действуют на все блоки сразу и сохраняются в URL (`?pipeline=...&manager=...&date=...`), чтобы ссылкой можно было поделиться.

### 2. Плитки-метрики (вместо семи одинаковых чисел)

Две группы с подписями.

«Требуют внимания» (чем меньше, тем лучше):
- Просроченные дела: число, дельта ко вчерашнему снимку, подсказка «самая старая: 42 дня».
- Сделки без дел: число и сумма этих сделок («34 сделки · 2,1 млн ₽»).
- Зависшие сделки: число, сумма и медиана рабочих дней на стадии.
- Просроченные задачи: число и самая старая.

«Результат дня»:
- Выиграно: сумма и число сделок.
- Проиграно: сумма, число и главная причина.
- Звонки: число и сравнение с нормой (норму задаём в конфиге). Если звонков 0, а у менеджеров есть сделки в работе, показывать серую плашку «нет данных о звонках, проверьте интеграцию телефонии» вместо красного нуля.
- Счета: выставлено, оплачено, просрочено.

Каждая плитка:
- цвет полоски-акцента по порогам: зелёный, жёлтый или красный (пороги в конфиге, пример: зависших больше 20 = красный);
- мини-спарклайн за 14 последних снимков (Recharts `AreaChart` высотой 32px без осей), чтобы видно было, копится завал или тает;
- клик по плитке открывает соответствующий раздел с уже применённым фильтром.

### 3. Карта менеджеров (главный новый блок)

Вместо трёх списков «менеджер: количество» сделать одну тепловую таблицу:
- строки: менеджеры (чип с инициалами, имя);
- колонки: Просроченные дела, Без дел, Зависшие, Просроченные задачи, Звонки, Выиграно, Проиграно;
- в ячейке число, фон ячейки по интенсивности (от прозрачного до красного для проблемных колонок, до зелёного для «Выиграно»);
- последняя колонка «Сумма под риском»: сумма сделок менеджера, которые висят или без дел;
- сортировка по клику на любой заголовок (иконка `ArrowUpDown`), по умолчанию по сумме проблем;
- клик по строке ставит фильтр по этому менеджеру на весь отчёт.

Рядом или под ней горизонтальная stacked-диаграмма (Recharts `BarChart layout="vertical"`): у каждого менеджера полоса из сегментов по типам проблем. Так видно, у кого завал и из чего он состоит.

### 4. «Проблемные сделки»: одна таблица вместо трёх вкладок

Объединить «Просроченные дела», «Без дел» и «Зависшие» в одну таблицу по сделкам. У каждой сделки теги проблем:
- «просрочено дело · 42 дн» (красный);
- «нет дел» (жёлтый);
- «на стадии 21 раб. дн» (оранжевый, если больше порога).

Колонки: Сделка (ссылка в Bitrix24, открывается в новой вкладке, иконка `ExternalLink`), Проблемы (теги), Менеджер, Воронка (цветной чип), Стадия (название плюс мини-индикатор положения стадии в воронке: 5 точек, закрашены пройденные), Сумма, Последняя активность («3 дня назад»), Дней на стадии.

Поведение:
- сверху быстрые фильтры-чипы: «Все 52», «Просрочено дело 5», «Без дел 34», «Зависли 38», «Больше 30 дней 12»;
- поиск по названию сделки;
- группировка по менеджеру с раскрытием и сворачиванием групп (`ChevronDown`), в заголовке группы число сделок и сумма;
- в подвале таблицы итог: число сделок и сумма;
- сортировка кликом по заголовку, липкий заголовок при прокрутке;
- сделки, которые попали сразу в несколько проблем, наверху (у них больше тегов).

Отдельные вкладки «Просроченные дела» и «Без дел» оставить как детальные виды с деталями дела (тип, название, дедлайн), но открывать их из этой таблицы кликом по тегу.

### 5. Просрочка: понятные бейджи

Правило для колонок «Дней просрочки» и «Дедлайн»:
- просрочено сегодня: жёлтый бейдж «сегодня» (не красный «0»);
- 1-3 дня: жёлтый «2 дня»;
- 4-14 дней: оранжевый;
- 15 и больше: красный.

Дедлайн показывать относительно: «вчера, 20:00», «28 сент., 12:00», а точную дату в `title` при наведении.

### 6. Зависшие: распределение по возрасту

Гистограмма (Recharts `BarChart`) по корзинам рабочих дней на стадии: 5-10, 11-20, 21-40, 41-80, больше 80. Столбцы окрашены от жёлтого к красному, над столбцом число сделок и сумма. Переключатель «по воронкам / по стадиям»: какие стадии чаще всего становятся болотом (в текущих данных это «Работы завершены» и «Передано в отдел разработки»).

### 7. Выигранные и проигранные

- Две плитки с суммами и числом, соотношение выиграно / проиграно полосой.
- Проигранные: горизонтальные бары по причинам отказа с суммами.
- Таблица сделок: Сделка, Менеджер, Воронка, Сумма, Дата закрытия, Причина (для проигранных).
- Тренд за 30 дней: выиграно и проиграно по дням (`AreaChart`, зелёная и красная области).

### 8. Звонки

- Столбцы по менеджерам: входящие, исходящие, пропущенные (stacked), линия нормы.
- Если данных нет совсем, показывать пустое состояние с пояснением, а не нули.

### 9. Счета

Плитки «Выставлено / Оплачено / Просрочено» с суммами, таблица счетов со статусом-бейджем, сроком оплаты и днями просрочки (те же цветовые правила, что в разделе 5).

### 10. Пустые и служебные состояния

- Пустой раздел показывать позитивно: иконка `CheckCircle`, «Просроченных задач нет».
- Загрузка: скелетоны тех же размеров, что и карточки.
- Ошибка API: карточка с текстом и кнопкой «Повторить» (`RefreshCw`).
- В подвале: время снимка, источник, кнопка «Экспорт в CSV» для текущей таблицы с учётом фильтров.

## Навигация

Вкладки-пилюли оставить, но:
- рядом с названием вкладки счётчик-бейдж с числом и цветом по порогу («Зависшие 38» красным);
- порядок по важности: Обзор, Проблемные сделки, Менеджеры, Просроченные задачи, Звонки, Выигранные, Проигранные, Счета;

## Контракт данных (JSON с бэкенда)

```ts
interface OpsSnapshot {
  meta: {
    snapshotAt: string;          // ISO, время снимка
    date: string;                // YYYY-MM-DD
    timezone: string;            // "Europe/Moscow"
    portalUrl: string;           // для ссылок на сделки, без токена вебхука
    currency: "RUB";
    thresholds: {                // пороги цветов для плиток и бейджей
      stuckWorkDays: number;     // с какого дня сделка считается зависшей
      stuckRed: number;          // сколько зависших = красная плитка
      noActivityRed: number;
      callsNormPerManager: number;
    };
  };
  managers: { id: string; name: string }[];
  pipelines: { id: string; name: string; color?: string }[];
  stages: { id: string; pipelineId: string; name: string; sort: number; semantics: "P" | "S" | "F" }[];
  deals: {
    id: string;
    title: string;
    managerId: string;
    pipelineId: string;
    stageId: string;
    amount: number;
    createdAt: string;
    stageSince: string;
    workDaysOnStage: number;     // рабочие дни считаются на бэкенде (с учётом праздников РФ)
    lastActivityAt: string | null;
    hasOpenActivities: boolean;
  }[];
  overdueActivities: { id: string; dealId: string; type: string; title: string; deadline: string; managerId: string }[];
  overdueTasks: { id: string; title: string; deadline: string; managerId: string; dealId: string | null }[];
  calls: { managerId: string; date: string; incoming: number; outgoing: number; missed: number }[] | null; // null = нет интеграции
  closedDeals: { dealId: string; result: "won" | "lost"; closedAt: string; amount: number; lossReason: string | null }[];
  invoices: { id: string; dealId: string; amount: number; status: "sent" | "paid" | "overdue"; dueDate: string; paidAt: string | null }[];
  history: { date: string; overdueActivities: number; noActivities: number; stuck: number; overdueTasks: number; won: number; lost: number }[]; // 30 последних снимков для дельт и спарклайнов
}
```

Все производные вещи (теги проблем, корзины возраста, суммы под риском, дельты ко вчера) считаются на клиенте из этого JSON.

## Качество

- TypeScript strict, без `any`.
- Проверить на ширине 375px, 768px и 1440px, в тёмной и светлой теме.
- Контраст текста не ниже WCAG AA. Цвет никогда не единственный носитель смысла: у каждого цветного бейджа есть текст.
- Таблица на 500 сделок не должна тормозить: фильтрация и сортировка в `useMemo`, без пересчёта на каждый рендер.
- В консоли браузера нет ошибок.
